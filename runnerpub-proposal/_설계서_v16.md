## 라운드 B 가 잡아낸 가장 큰 것 — 내 검증 방법이 틀렸다

라운드 A 때 나는 「결론 띠에 노란 형광이 살아 있다」는 지적을 **오진이라고 사장님께
보고했다.** PPTX XML 을 열어 `FFE96B` 0건을 확인했다고 적었다. **그 보고가 틀렸다.**

라운드 B 가 같은 지적을 다시 올렸고, 이번엔 완전 빌드 후 다시 열어 보니 **2건이 실재했다.**

```
ppt/slides/slide2.xml   #FFFFFF «개설 이후 구조는 러너펍이 완비 · 계약 이전 구간의 »
                        #FFE96B «창업 수요는 내일사장이 보유»      ← 노란 형광
ppt/slides/slide9.xml   #FFFFFF «미위임 시 채용 고정비와 … 위임 시 »
                        #FFE96B «계약 성사 건에만 비용 발생»       ← 노란 형광
```

**원인은 내 명령어였다.** `node mk10.js 2>&1 | head -8` 로 빌드했는데, `mk10.js` 는
`p.writeFile(...).then(...)` 로 **비동기 저장**한다. `head` 가 파이프를 먼저 닫으면
node 가 저장을 끝내기 전에 끊긴다. 그래서 내가 열어 본 PPTX 는 **직전 판**이었고,
그 판에는 마침 형광이 없었다. 검사 대상이 아니라 검사 **방법**이 틀렸던 것이다.

이후 모든 빌드는 `node mk10.js > log 2>&1` 로 바꿨다.
