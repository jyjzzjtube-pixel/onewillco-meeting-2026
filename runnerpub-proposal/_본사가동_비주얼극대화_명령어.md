# 본사가동 · 비주얼 극대화 모드 — 명령어

> 디자인 · 이미지 · 배색 · 배경 · 폰트 · 아이콘을 **끝까지 쓰게 만드는** 명령어.
> 대괄호만 채워서 그대로 붙여넣는다.

---

## ■ 명령어 본문 (이것만 복사)

```
본사가동 비주얼 극대화 모드. 최적화 아니라 극대화다.

━━━ 0. 전제
  텍스트만 얹은 문서는 산출물로 인정하지 않는다.
  "여백을 살렸다" "정제된 톤" 은 변명으로 본다.
  한 장을 열었을 때 눈이 먼저 잡는 물체가 없으면 그 장은 실패다.

━━━ 1. 산출물
  형식   : [PPTX 16:9]   분량 : [15]장
  폰트   : [맑은 고딕]  — 타 PC 호환 필수, 임베딩 금지
  파일명 : [러너펍_제안서_내일사장_202607.pptx]
  위치   : [/home/user/onewillco-meeting-2026/runnerpub-proposal/]

━━━ 2. 사실 원천 (여기 밖의 숫자·실적·고객사명 생성 금지)
  [_brief.md] [_brief_naeilsajang.md]
  없으면 먼저 자료를 뒤져 원천 파일부터 만들고 확인받아라.
  구글드라이브 · T7 SSD · Gmail · 노션 전부 뒤져라. 못 찾으면 "없다"고 말하고 멈춰라.

━━━ 3. 톤앤매너 레퍼런스
  [내일사장 IR / 사업소개서]
  전 페이지를 이미지로 렌더해서 한 장씩 눈으로 보고,
  색 · 타이포 · 레이아웃 골격 · 전개 순서를 "문법"으로 뽑아 적용해라.
  "비슷하게"가 아니라 "같은 문법으로".

━━━ 4. 비주얼 강제 규격 (전 장 검사 · 위반 시 그 장 다시)
  [배경]  순색 풀블리드 면을 전체의 25~35%에 깐다.
          흰 배경만 연속 3장 이상 금지. 챕터 표지는 무조건 순색 면.
  [분할]  좌우 명암분할(한쪽 다크 / 한쪽 라이트)을 최소 [3]장에 쓴다.
  [면적]  본문 영역의 40% 이상을 도형 · 이미지 · 그래프 · 표가 차지한다.
          글자만 있는 장 0장.
  [수치]  각 장에 시선을 잡는 대형 수치 최소 1개. 28pt 이상.
          핵심 숫자는 형광(노랑) 또는 순색 칩으로 물리적으로 강조.
  [아이콘] 체크 · 화살표 · 핀 · 단계 배지 등 포인트 아이콘을 전 장에 배치.
          기성 이모지 금지. 코드로 그려서 선굵기 · 비율 · 색을 통제해라.
  [하단]  전 장 하단에 결론 한 줄 밴드. 문장형 / 수치형 / 칩형 3종을 번갈아 쓴다.
  [반복]  머리(챕터번호 · 로고) · 발(발신→수신 · 쪽번호) 골격은 15장 전부 동일.
          내용은 매 장 다르게, 골격은 매 장 같게.

━━━ 5. 배색 (여기서 벗어나지 마라)
  주      : 네이비 #16233D / #1D2C47
  강조    : 블루 #2C68F3   보조 #7FA8FF
  배경틴트: #E8EFFF / #D3E0FF / #EEF3FF
  경고    : 레드 #E23B3B   형광 : 옐로 #FFE96B
  지면    : #F2F4F8   흰색 #FFFFFF   다크 위 글자 #F4F6FA
  약한글자: #6C7891 (라이트) / #93A0B8 (다크)
  괘선    : #D6DCE7 (라이트) / #2B3A56 (다크)
  → 색은 6개까지만. 7번째 색을 쓰고 싶으면 그건 레이아웃 실패다.

━━━ 6. 타이포 (크기를 겹치지 마라 · 위계가 눈에 보여야 한다)
  영문앵커 32pt Bold  /  국문헤드 26pt Bold  /  2줄용 헤드 24pt Bold
  리드 13pt  /  소제목 14pt Bold  /  본문 11.5pt  /  카드 10.5pt
  라벨 9pt Bold 자간 +0.8  /  주석 8.5pt  /  대형수치 28~60pt Bold 자간 -1
  → 인접 위계는 최소 2pt 차이. 굵기만 다른 같은 크기 금지.

━━━ 7. 이미지 (없다고 넘어가지 마라)
  1순위 : 사내 자료(IR · 소개서 · PDF)에서 추출. 원본 비율 그대로.
  2순위 : 코드로 직접 그린다(PIL 4배 슈퍼샘플링). 선굵기 · 색 · 여백을 좌표로 통제.
  3순위 : 없으면 도형 · 그래프로 대체. 빈칸으로 두지 마라.
  다크 면에 얹는 이미지는 라이트 라인 버전을 따로 만든다. 어두운 선 얹지 마라.
  로고 · 사진 가장자리 잘림 0. 눌림 0. 원본 비율 오차 1.5% 이내.

━━━ 8. 검증 (코드로 만들어라 · 위반 시 빌드가 죽게 해라)
  □ 좌표 : 영역 이탈 0 · 텍스트 넘침 0 · 요소 겹침 0
  □ 이미지 : PNG 헤더에서 원본 크기 읽어 배치 비율과 대조, 오차 1.5% 이내
  □ 가독 : 다크 면 위 어두운 글자 0건 / 라이트 면 위 흰 글자 0건
           (배경 색상과 글자 색상 대비를 좌표 단위로 대조해라)
  □ 밴드 : 풀블리드 요소가 푸터 · 쪽번호를 덮지 않는가
  □ 사실 : 사실 원천 밖 숫자 0건
  □ 방향 : 발신 [내일사장] → 수신 [러너스튜디오(주)] 전 장 일관
  "눈으로 확인했다"는 근거가 아니다. 검사기를 통과한 수치만 근거다.

━━━ 9. 렌더 검수 (필수 · 생략 금지)
  빌드 후 전 장을 이미지로 렌더해서 실제로 봐라.
  한 장씩 보고 아래를 확인해라.
    · 헤드라인이 배경에 먹히지 않았는가
    · 이미지가 배경색에 묻히지 않았는가
    · 표 · 카드 안 글자가 상자 밖으로 나가지 않았는가
    · 아이콘이 무엇인지 알아볼 수 있는가
  안 보이면 색을 바꾸는 게 아니라 구조를 바꿔라.

━━━ 10. 네가 결정할 것 (묻지 말고 진행)
  배색 조합 · 폰트 크기와 굵기 · 레이아웃 · 장 순서 · 이미지 배치 ·
  아이콘 형태 · 문장 다듬기 · 장수 조정 · 삭제와 통합

━━━ 11. 나에게 물을 것 (이것만)
  금액 · 수수료율 · 계약 조건 등 돈에 관한 새 조건
  담당자 실명 · 연락처
  사실 원천에 없어서 확인이 필요한 실적

━━━ 12. 금지
  없는 숫자 · 실적 · 고객사명 생성
  개인정보(고객 실명 · 연락처 · 계정) 산출물 반입
  [포카드 등 홀덤 업종 이력] 주장 또는 암시
  기성 아이콘 폰트 · 이모지 · 스톡 클립아트
  "~해도 될까요" 되묻기 — 위 결정 범위 안이면 그냥 해라
  작업 과정 장황한 설명 — 결과와 검증 수치만

━━━ 13. 진행 방식
  1단계 아이디어회의 — 레퍼런스 렌더 분석 + 현재물 진단.
                      최소 3개 관점(비주얼 / 전개 / 수신자)이 독립적으로.
  2단계 기획설계     — 회의 결과를 설계서 하나로 확정. 나열 말고 결정.
                      장별 배경 · 분할 · 대형수치 · 아이콘 · 밴드 종류를 표로 못 박아라.
  3단계 적용         — 설계서대로 구현. 검사기부터 만들고 그 위에 그려라.
  4단계 검수         — 8·9번 전부 통과할 때까지 반복.
  종료 조건 : 2라운드 연속 critical · high 0건

━━━ 14. 보고 형식
  검증 수치 표 + 어필 포인트가 몇 쪽 어디에 어떤 크기로 들어갔는지 + 남은 결정 사항.
  중간 보고 불필요. 다 되면 파일과 함께 한 번에.
```

## ■ 상황별 추가 한 줄

| 상황 | 붙일 문구 |
|---|---|
| 더 세게 | `+ 지금 것보다 시각 밀도를 두 배로. 흰 여백이 보이면 정보를 넣어라.` |
| 더 차분하게 | `+ 순색 면은 챕터 표지에만. 나머지는 라이트 + 강조색 1개.` |
| 처음부터 | `+ 기존 산출물은 참고만. 재활용 금지. 설계부터 다시.` |
| 자료 위치 모를 때 | `+ 자료는 구글드라이브 · T7 SSD · Gmail · 노션 어딘가에 있다. 네가 찾고 목록부터 보고해라.` |
| 이미지 없을 때 | `+ 이미지는 사내 PDF에서 추출 1순위, 없으면 코드로 그려라. 출처와 방식 보고.` |
| 검수만 | `본사가동 검수모드. 대상 [경로]. 관점 비주얼 / 전개 / 수신자 / 사실검증 4개. 지적마다 쪽수·좌표·인용 근거. critical·high만 고치고 나머지는 목록으로.` |
