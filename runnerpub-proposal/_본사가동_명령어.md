# 본사가동 프로모드 — 명령어 템플릿

> 이 세션에서 **실패한 원인**과 **통했던 방식**을 그대로 반영한 양식입니다.
> 대괄호만 채워서 그대로 붙여넣으면 됩니다.

---

## 0. 왜 이 양식인가 (실패 원인 5가지)

| 실패 | 원인 | 이 양식의 해결 |
|---|---|---|
| 없는 숫자·조건을 지어냄 | 사실 원천이 없었음 | §2 사실 원천 고정 |
| 글자 짤리고 영역 이탈 | 눈대중 배치 | §4 검증 기준을 코드로 |
| 로고 눌리고 잘림 | 원본 비율 미확인 | §4 이미지 비율 검사 |
| 디자인이 계속 반려됨 | 톤앤매너 기준이 없었음 | §3 레퍼런스 지정 |
| 자꾸 되물어서 진행이 안 됨 | 판단 위임 범위가 없었음 | §5 결정권 명시 |

## 1. 명령어 본문 (복사해서 사용)

```
본사가동 프로모드.

■ 산출물
  형식     : [PPTX 16:9 / A4 세로 PDF / DOCX / HTML]
  분량     : [15]장
  폰트     : [맑은 고딕] — 타 PC 호환 필수
  파일명   : [러너펍_제안서_내일사장_202607.pptx]
  최종 위치: [/home/user/onewillco-meeting-2026/runnerpub-proposal/]

■ 사실 원천 (여기 밖의 숫자·실적·조건은 절대 생성 금지)
  [runnerpub-proposal/_brief.md]
  [runnerpub-proposal/_brief_naeilsajang.md]
  없으면: 먼저 자료를 뒤져 사실 원천 파일부터 만들고 나에게 확인받아라.
  구글드라이브·Gmail·노션도 뒤져라. 못 찾으면 "없다"고 말하고 멈춰라.

■ 톤앤매너 레퍼런스 (이 문서의 문법을 따른다)
  [내일사장 IR v1.3 / 사업소개서]
  전 페이지를 이미지로 렌더해서 한 장씩 눈으로 보고,
  색·타이포·레이아웃 골격·전개 순서를 문법으로 뽑아낸 뒤 적용해라.
  "비슷하게"가 아니라 "같은 문법으로".

■ 어필 포인트 (우선순위 순 · 이게 안 보이면 실패)
  1. [프랜차이즈 본사 출신 4인이 직접 영업 — SPC 파리바게뜨·이삭토스트·맥도날드·아딸]
  2. [실제 가맹영업 수행 이력 — 33떡볶이 강동역점 등 수행 브랜드 30여 개]
  3. [계약된 건에만 비용 발생 — 본사 리스크 0]
  4. [앱 10만·월 5만·상담DB 5,114명 — 모수를 새로 만들 필요 없음]
  각 항목이 몇 쪽 어디에 어떤 크기로 들어갔는지 보고할 것.

■ 검증 기준 (전부 통과해야 완료 · 하나라도 실패하면 미완성)
  □ 좌표: 영역 이탈 0 · 텍스트 넘침 0 · 요소 겹침 0
  □ 이미지: 원본 비율 대비 오차 1.5% 이내 · 가장자리 짤림 0
  □ 사실: 사실 원천 밖 숫자 0건
  □ 방향: 발신 [내일사장] → 수신 [러너스튜디오(주)] 전 페이지 일관
  검사를 코드로 만들어라. 위반 시 빌드가 죽게 해라. 눈으로 확인했다는 말은 근거가 아니다.

■ 네가 결정할 것 (묻지 말고 진행)
  색 조합, 폰트 크기·굵기, 레이아웃, 장 순서, 이미지 배치, 문장 다듬기,
  장수 조정, 삭제·통합 판단

■ 나에게 물을 것 (이것만)
  금액·수수료율·계약 조건 등 돈에 관한 새 조건
  담당자 실명·연락처
  사실 원천에 없어서 확인이 필요한 실적

■ 금지
  없는 숫자·실적·고객사명 생성
  개인정보(고객 실명·연락처·계정) 산출물 반입
  "~해도 될까요" 되묻기 — 위 결정 범위 안이면 그냥 해라
  작업 과정 장황한 설명 — 결과와 검증 수치만 보고

■ 진행 방식
  1단계 아이디어회의 — 레퍼런스 분석 + 현재물 진단, 최소 3개 관점(비주얼/전개/수신자)
  2단계 기획설계   — 회의 결과를 하나의 설계서로 확정. 나열 말고 결정
  3단계 적용       — 설계서대로 구현
  4단계 검수       — 위 검증 기준 전부 통과할 때까지 반복
  종료 조건: 2라운드 연속 critical·high 0건

■ 보고 형식
  완료 시: 검증 수치 표 + 어필 포인트 배치 위치 + 남은 결정 사항
  중간 보고 불필요. 다 되면 파일과 함께 한 번에.
```

## 2. 상황별 추가 문구

**빨리 봐야 할 때**
```
+ 3단계까지만 하고 초안 보여줘. 검수는 내 확인 후에.
```

**완전히 다시 만들 때**
```
+ 기존 산출물은 참고만 하고 처음부터 다시 설계해라. 재활용 금지.
```

**자료가 어딨는지 모를 때**
```
+ 자료는 구글드라이브·T7 SSD·Gmail·노션 어딘가에 있다. 네가 찾아라.
  찾은 파일 목록을 먼저 보고하고 진행해라.
```

**이미지가 필요할 때**
```
+ 이미지는 사내 자료(IR·소개서·PDF)에서 추출하는 것을 1순위로 하고,
  없으면 코드로 직접 그려라. 추출·생성 방식과 원본 출처를 보고해라.
```

**검수만 시킬 때**
```
본사가동 검수모드.
대상: [파일 경로]
관점: 비주얼 / 전개 / 수신자(러너펍 본부장) / 사실검증 4개
각 지적마다 근거(쪽수·좌표·인용)를 대라. 추측 금지.
severity critical·high만 고치고, medium 이하는 목록으로 보고해라.
```

## 3. 이 세션에서 실제로 통했던 것

**사실 원천 파일** — `_brief.md`에 확정 조건을 박아두니 검수관이 "이 숫자는 원천에 없다"고 잡아냄. 지어내기 18건 적발.

**좌표 검사기** — `grid.js`. 영역을 선언하고 벗어나면 빌드가 죽게 하니 짤림이 구조적으로 불가능해짐. 첫 실행에서 내 계산 오류 0.218인치를 즉시 검출.

**이미지 비율 검사기** — PNG 헤더에서 원본 크기를 읽어 배치 비율과 대조. 로고 눌림의 원인이었던 5.69 대 3.70 불일치를 잡음.

**레퍼런스 렌더 분석** — IR 14장을 이미지로 뽑아 3개 관점이 각각 전부 훑음. "순색 네이비 면이 14장 중 0장" 같은 관찰은 실제로 봐야만 나옴.

**다관점 회의** — 비주얼·전개·수신자 3개 관점이 독립적으로 같은 결론에 도달("같은 회사 문서로 안 보인다"). 한 관점만으로는 못 잡음.
